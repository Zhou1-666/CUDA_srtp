# PaScaL 三/五对角程序正确性与性能运行手册

> 版本：v1.0  
> 日期：2026-08-17  
> 源码目录：`CUDA_coding/CUDA_code/源代码`  
> 目标：从数学验证、干净构建、单/多 rank 正确性到真实多 GPU 性能，形成可复现证据

## 0. 先读：当前可信边界

当前可以立即信任并复现的是五项独立 Node 数学验证和历史 CSV 的静态分析。

当前三/五对角模块都存在一个 P0：阻塞式 `MPI_ALLTOALLV` 后对未初始化 request 数组调用 `MPI_WAITALL`：

- `src/PaScaL_TDMA_cuda.f90` 约 735–736 行；
- `src/PaScaL_TDMA_cuda_penta.f90` 约 1026–1027 行。

因此：

- `np=1` 不经过多 rank 缩约通信，可用于单 GPU直接路径验证；
- `np>1` 当前只能用于诊断，不能作为发布/论文正确性和性能证据；
- P0 修复、干净重建并完成多 rank 回归后，才能执行本手册的正式扩展实验。

另一个注意点：benchmark 同时向 stdout 输出 CSV 行和人类可读汇总。保存结果后要按本手册清洗，只保留 CSV 表头和以 `penta,` 开头的数据行。

## 1. 验证层级

| 层级 | 回答的问题 | 当前能否运行 |
| --- | --- | --- |
| V0 知识/文件检查 | 文档、链接和来源是否一致 | Windows 可运行 |
| V1 独立数学验证 | 算法、递推和槽位结构是否正确 | Windows/Node 可运行 |
| V2 干净构建 | NVHPC/MPI/API 能否从零编译 | 需 Linux/WSL/HPC |
| V3 单 rank GPU | 五对角直接 kernel 是否正确 | 需 NVHPC + GPU |
| V4 多 rank GPU | MPI 缩约链路是否正确 | P0 修复后运行 |
| V5 性能基准 | 哪个阶段耗时，优化是否有效 | P0 修复后运行 |
| V6 真实多 GPU | 强/弱扩展和论文性能 | HPC、每 rank 独占 GPU |

只有前一层通过，才能把后一层结果作为正式证据。

## 2. Windows 上立即运行数学验证

打开 PowerShell：

```powershell
Set-Location 'D:\CUDA\CUDA_repository\CUDA_coding\CUDA_code\源代码'

node verify/penta_indep_check.js
node verify/penta_comm_28_verify.js
node verify/hepta_indep_check.js
node verify/mband_general.js
node verify/mband_recurrence.js
```

每条命令退出码都应为 0。可以在命令后检查：

```powershell
$LASTEXITCODE
```

当前已知参考结果：

| 脚本 | 参考输出 |
| --- | --- |
| `penta_indep_check.js` | 72 组，最大差约 `2.887e-15` |
| `penta_comm_28_verify.js` | 756 组，0 失败，最坏相对误差约 `7.594e-14` |
| `hepta_indep_check.js` | 54 组，最大差约 `1.443e-15` |
| `mband_general.js` | 216 组，最坏差约 `6.661e-16` |
| `mband_recurrence.js` | 108 组，完整解最大差约 `6.661e-16` |

判定：任一脚本退出非 0、出现失败配置、NaN/Inf，或误差相对上述结果大幅恶化，都不得继续宣称算法正确。

这些脚本只能证明独立数学模型，不证明 CUDA/MPI 实现没有越界、竞态或通信错误。

## 3. 检查 Linux/WSL/HPC 环境

进入源码目录后运行：

```bash
cd /你的路径/源代码
bash hpc/check_env.sh | tee env_check.txt
```

至少确认：

```bash
command -v nvfortran
command -v mpif90
command -v mpirun
command -v make
nvfortran --version
mpif90 --version
nvidia-smi
nvidia-smi topo -m
```

关键要求：

- `mpif90` 必须实际包装兼容的 NVHPC/nvfortran；
- 驱动与 NVHPC 使用的 CUDA 版本兼容；
- 多 GPU 时知道每节点 GPU 数和 rank→GPU 映射；
- CUDA-aware MPI 必须用 device-buffer 最小测试确认，不能仅凭名称推断。

如果是超算，登录节点只用于环境检查、编译和提交，不要在登录节点直接运行重型 benchmark。

## 4. 干净构建主库和示例

在源码根目录：

```bash
cd /你的路径/源代码
make veryclean
make all 2>&1 | tee build_all.log
```

检查产物：

```bash
ls -lh lib/libPaScaL_TDMA.a
ls -lh include/*.mod
ls -lh run/a.out run/a.out_penta
```

若需要指定架构，先确认 GPU compute capability，再尝试：

```bash
make veryclean
make CUDAFLAG="-cuda -gpu=cc80" all 2>&1 | tee build_cc80.log
```

示例：A100 常用 `cc80`，H100 常用 `cc90`，RTX 4060 Laptop 常用 `cc89`。实际以目标 NVHPC 和 GPU 为准；如果指定 `ccXX` 导致工具链版本检查失败，先使用默认 `-cuda` 验证正确性。

构建通过标准：

- 命令退出码 0；
- 没有未解析符号或 module 不匹配；
- 产物是在当前环境干净生成，不是历史 `.o/.mod`；
- 保存 `build_all.log`、编译器版本和 flags。

## 5. 运行主库示例

### 5.1 单 rank 三对角

```bash
mpirun -np 1 ./run/a.out | tee tri_np1.log
```

### 5.2 单 rank 五对角

```bash
mpirun -np 1 ./run/a.out_penta | tee penta_np1.log
```

示例程序主要用于检查初始化、GPU 分配、API 调用和输出是否正常，不提供完整误差范数。正式正确性以 `perf_bench` 的 exact/manufactured 测试为准。

### 5.3 多 rank 示例

P0 修复前不要把下面结果作为证据。修复后，每个 rank 应尽量独占一块 GPU：

```bash
mpirun -np 2 ./run/a.out_penta | tee penta_np2.log
```

检查所有 rank 都完成、没有 hang、MPI error、CUDA error、NaN/Inf，并且分区输出连续。

## 6. 构建五对角正确性/性能 benchmark

```bash
cd /你的路径/源代码/perf_bench
make veryclean
make 2>&1 | tee build_benchmark.log
ls -lh benchmark_penta
```

如果 MPI wrapper 不合适，可以显式指定：

```bash
make veryclean
make FC="nvfortran -Mmpi" 2>&1 | tee build_benchmark_mpi.log
```

或按集群实际路径指定 NVHPC 自带 `mpif90`。

benchmark 参数：

```text
./benchmark_penta n1 n2 n3 iterations tdma_threads reduced_threads
```

默认测试是 `exact1`，环境变量 `PENTA_TEST_CASE=manufactured` 选择非平凡制造解。

## 7. 单 rank 正确性验证

### 7.1 常数精确解

```bash
cd /你的路径/源代码/perf_bench
mpirun -np 1 ./benchmark_penta 64 64 1024 3 128 128 | tee np1_exact1.log
```

### 7.2 非平凡制造解

```bash
PENTA_TEST_CASE=manufactured \
mpirun -np 1 ./benchmark_penta 64 64 1024 3 128 128 | tee np1_manufactured.log
```

重点查看末尾：

```text
solver     avg_time(s)  err_rms  err_linf  cross_err
```

P0 修复后冻结正式 baseline 前，可使用以下开发阈值：

```text
err_rms       <= 1e-10
err_linf      <= 1e-10
cross_err_max <= 1e-10
```

历史结果通常在 `1e-12` 左右。阈值 `1e-10` 是开发 Gate，不表示论文应只报告到这一精度；论文必须报告实际误差。

## 8. 多 rank 正确性验证

仅在 P0 修复、重新编译后执行。

```bash
PENTA_TEST_CASE=exact1 \
mpirun -np 2 ./benchmark_penta 64 64 1024 3 128 128 | tee np2_exact1.log

PENTA_TEST_CASE=manufactured \
mpirun -np 2 ./benchmark_penta 64 64 1024 3 128 128 | tee np2_manufactured.log
```

然后扩展到 4 rank：

```bash
PENTA_TEST_CASE=manufactured \
mpirun -np 4 ./benchmark_penta 128 128 2048 5 128 128 | tee np4_manufactured.log
```

通过标准：

- 所有进程正常结束；
- exact1 与 manufactured 均过误差 Gate；
- `cross_err_max` 过 Gate；
- `nrow_min/nrow_max` 与预期分区一致；
- rank 数改变没有导致数量级误差增长；
- 没有 MPI/CUDA error 或 hang。

单 GPU 上可以用多 rank 检查通信正确性，但不能用来证明多 GPU 性能。

## 9. 快速性能冒烟

P0 修复后：

```bash
cd /你的路径/源代码/perf_bench
STUDY_PRESET=quick ITERATIONS=5 ./run_sweep.sh
```

它会生成：

```text
<时间戳>_penta_perf.csv
<时间戳>_penta_env.txt
```

找到最新文件：

```bash
ls -1t *_penta_perf.csv | head -1
ls -1t *_penta_env.txt | head -1
```

### 9.1 检查并清洗 CSV

现版脚本可能把屏幕汇总混入 `.csv`。先检查：

```bash
CSV=$(ls -1t *_penta_perf.csv | head -1)
grep -n -v -E '^(solver,|penta,)' "$CSV" | head
```

如果有输出，说明存在非 CSV 行。生成干净文件：

```bash
awk '/^solver,/ || /^penta,/' "$CSV" > "${CSV%.csv}_clean.csv"
CLEAN="${CSV%.csv}_clean.csv"
```

如果没有污染：

```bash
CLEAN="$CSV"
```

## 10. 正式强/弱扩展

这些实验必须在每 rank 独占 GPU 的真实多 GPU 环境执行。

### 10.1 强扩展

固定全局规模，改变 GPU/rank 数：

```bash
STUDY_PRESET=strong \
NP_LIST="1 2 4 8" \
ITERATIONS=10 \
./run_sweep.sh
```

### 10.2 弱扩展

保持每 GPU 工作量近似固定：

```bash
STUDY_PRESET=weak \
NP_LIST="1 2 4 8" \
ITERATIONS=10 \
./run_sweep.sh
```

### 10.3 自定义规模

```bash
STUDY_PRESET=custom \
NP_LIST="1 2 4" \
SIZE_LIST="128,128,2048 128,128,4096" \
ITERATIONS=10 \
./run_sweep.sh
```

每增加一档规模，先确认上一档误差正常、显存未超限。

## 11. HPC/Slurm 运行

### 11.1 首次环境探测

```bash
cd ~/源代码/hpc
bash check_env.sh | tee check_env_$(date +%Y%m%d-%H%M%S).txt
```

先根据真实输出修改 Slurm 脚本中的：

- `--partition`；
- `--nodes`；
- `--ntasks-per-node`；
- `--gres=gpu:N`；
- `module load ...`；
- 临时目录和 MPI 特定环境变量。

仓库里的 nvhpc/A100/路径只是历史模板，不应原样假定适用于新集群。

### 11.2 单 GPU 自包含验证作业

```bash
cd ~/源代码/perf_bench
sbatch ~/源代码/hpc/submit_penta.slurm
squeue -u "$USER"
```

完成后：

```bash
ls -1t penta_v_*.out | head -1
ls -1t penta_v_*.err | head -1
```

### 11.3 多 GPU benchmark

P0 修复且单 GPU/2 rank 正确性通过后：

```bash
cd ~/源代码/perf_bench
PENTA_TEST_CASE=manufactured \
N1=128 N2=128 N3=2048 ITER=10 \
sbatch ~/源代码/hpc/run_benchmark.slurm
```

查询：

```bash
squeue -u "$USER"
sacct -j <jobid> --format=JobID,State,Elapsed,ExitCode,AllocTRES
```

## 13. 性能判定方法

### 13.1 主要指标

- `total_s_max`：主要端到端墙钟；
- `local_compute_s_max`：S1；
- `pack/unpack_*`：布局和打包；
- `mpi_forward/backward_s_max`：两次通信；
- `reduced_compute_s_max`：`4P` 缩约求解；
- `update_compute_s_max`：S6；
- `err_rms/err_linf/cross_err_max`：正确性 Gate。

### 13.2 统计

每个配置预热后至少 5 次，论文建议 10 次。对重复结果报告：

- 中位数；
- IQR 或 MAD；
- 绝对时间；
- 加速比；
- 并行效率；
- 各阶段占 total 的比例。

### 13.3 优化是否成功

必须同时满足：

1. 正确性 Gate 不退化；
2. 相同硬件、规模、精度、rank/GPU 映射和编译 flags；
3. 绝对时间收益超过运行波动；
4. 若只改善阶段时间，只声明阶段收益；
5. 端到端 `total_s_max` 也改善，才声明端到端加速。

例如 28→22 表示 forward 数据槽减少约 21%，不自动表示 MPI 时间或总时间减少 21%。

## 15. 常见失败

| 症状 | 优先检查 |
| --- | --- |
| `nvfortran` 找不到 | 加载/安装 NVHPC |
| `-cuda` 不认识 | `mpif90` 实际不是 NVHPC wrapper |
| GPU 不可见 | 驱动/NVHPC CUDA 版本、作业是否申请 GPU |
| `np=1` 对、`np>1` hang/crash | 当前 P0 WAITALL、MPI 模式、rank→GPU |
| `err_linf` 很大 | case 初始化、分区、MPI 缩约、CUDA error |
| CSV 无法被 pandas 读取 | 清洗非 `solver,`/`penta,` 行 |
| 多 rank 更慢 | 是否单 GPU 过度订阅；不要误判算法扩展性 |
| 不同次结果波动大 | 预热、GPU 共享、频率、rank binding、同步和系统负载 |
| 大规模突然慢百倍 | 显存不足/统一内存页故障/多进程共享 GPU |

## 16. 最短执行清单

```text
1. Windows 跑五项 Node 验证
2. HPC/WSL 运行 check_env.sh
3. make veryclean && make all
4. mpirun -np 1 三/五对角示例
5. benchmark exact1 np=1
6. benchmark manufactured np=1
7. 修复 P0 后 benchmark manufactured np=2/4
8. quick sweep
9. 清洗 CSV，检查误差
10. 真实多 GPU strong/weak
11. 绘图并归档实验卡
```

正式正确性结论需要 V1–V4，正式性能结论需要 V1–V6。只跑通程序或只生成图都不等于验证完成。
