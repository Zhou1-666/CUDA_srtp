## 1. 项目目标

两个月内交付一个可复现的 CUDA Fortran + MPI 五对角求解器研究版本，并形成一篇证据完整的论文初稿/投稿包。项目不再以“搭建完整 CFD 软件”为目标，而以可集成进 CFD/PDE 软件的核心线性求解库为目标。

唯一主线：

> 在 PaScaL_TDMA 2.1 的分布式三对角思想上，验证并加固五对角扩展，利用缩约系统的结构零槽把前向数据从每线 28 个 double 裁剪到 22 个，并在真实多 GPU 环境评估正确性、通信与端到端性能。

一般半带宽 `m` 理论是论文的重要算法支撑，但两个月内不强制完成任意 `m` 的生产级 Fortran 实现。

红队评审后的执行原则：在进入 28→22 Fortran 实现前，先关闭“来源贡献边界、创新性/外部基线、冻结 28 槽基线”三类低成本高风险问题；真实多 GPU 环境不再等到第 6 周才首次接触，而要在第 1 周完成环境 smoke 和资源排期。

### 1.1 与原申报书的对齐方式

原申报书提出 FFT–批量 GMG、全显存驻留 CFD/PPE 等更大目标，当前源码尚未包含这些模块。为避免结题范围与申报书脱节，本计划增加一个**制造解 Poisson/Helmholtz 最小集成 demo**，证明带状求解器能作为 FFT 降维或高阶 CFD 离散的底层模块；若导师提供稳定的现有 CFD/FFT 主程序，则优先做真实接入。完整 FFT–GMG 和全流程 CFD 不在本轮从零实现，需由导师确认阶段性范围调整。详见 [[申报书目标与现有源码差距分析]]。

## 5. 论文设计

### 5.1 题目草案

中文：面向大规模 CFD 的通信裁剪多 GPU 五对角求解器：缩约结构、实现与性能评估  
英文：A Communication-Reduced Multi-GPU Pentadiagonal Solver for Large-Scale CFD Applications

题目需在文献检索与最终实验后再定稿。

### 5.2 预期贡献

1. 将 PaScaL 风格分布式缩约推广到五对角系统并给出可复现实现；
2. 给出一般半带宽 `m` 的接口规模、缩约带宽、槽位和通信公式；
3. 利用结构零槽把五对角前向数据从 28 裁剪到 22；
4. 在真实多 GPU 环境报告正确性、阶段性能、端到端性能与可扩展性。

贡献 2–4 必须由 TASK-013/019 的文献与证明审阅以及最终实验决定措辞强度。若一般 `m` 或 22 槽结构已有等价先例，则降级为实现/验证贡献；若没有公平外部实现，则不得把仓库内部参考组包装为领域最优基线。

### 5.3 必备图表

- 分布式六阶段算法/数据流图；
- 一般 `m` 缩约系统结构示意；
- 28 与 22 槽位映射图；
- 正确性误差/残差表；
- 28/22 通信字节与阶段耗时消融；
- 1/2/4/8 GPU 强、弱扩展；
- staging、persistent、CUDA-aware 对比；
- 外部 comparator 或“无公平 comparator”的检索与可比性表；
- profiler 或时间分解图。

## 6. 验收口径

### 正确性

- 独立 JS、CPU/稠密参考和 Fortran/MPI 结果形成三层证据；
- 不降低精度、不放宽残差来制造性能；
- 覆盖最小行长、不均匀分区、多个 rank 和重复 plan 调用；
- 覆盖弱对角占优、尺度跨度、近奇异/主元失败，并区分残差、前向误差和预期失败；
- 无未处理 MPI/CUDA 错误、NaN/Inf、越界和未初始化请求。

### 性能

- 同硬件、精度、规模、rank/GPU 映射和计时范围；
- 报告绝对时间，不只报告加速比；
- 预热后重复至少 5 次，报告中位数和波动；
- 区分 pack、通信、缩约求解、update 与 total；
- 单卡数据只作开发基线，真实多 GPU 才支持扩展性结论。
- 外部对照必须记录版本、算法范围和不可比项；不存在公平对照时明确报告，不以不同问题/精度制造优势。
