## 1. 项目目标

两个月内交付一个可复现的 CUDA Fortran + MPI 五对角求解器研究版本，并形成一篇证据完整的论文初稿/投稿包。项目不再以“搭建完整 CFD 软件”为目标，而以可集成进 CFD/PDE 软件的核心线性求解库为目标。

唯一主线：

> 在 PaScaL_TDMA 2.1 的分布式三对角思想上，验证并加固五对角扩展，利用缩约系统的结构零槽把前向数据从每线 28 个 double 裁剪到 22 个，并在真实多 GPU 环境评估正确性、通信与端到端性能。

一般半带宽 `m` 理论是论文的重要算法支撑，但两个月内不强制完成任意 `m` 的生产级 Fortran 实现。

### 1.1 与原申报书的对齐方式

原申报书提出 FFT–批量 GMG、全显存驻留 CFD/PPE 等更大目标，当前源码尚未包含这些模块。为避免结题范围与申报书脱节，本计划增加一个**制造解 Poisson/Helmholtz 最小集成 demo**，证明带状求解器能作为 FFT 降维或高阶 CFD 离散的底层模块；若导师提供稳定的现有 CFD/FFT 主程序，则优先做真实接入。完整 FFT–GMG 和全流程 CFD 不在本轮从零实现，需由导师确认阶段性范围调整。详见 [[申报书目标与现有源码差距分析]]。

## 2. 最终交付

### 必须完成

- 修复 P0 MPI 请求错误并补回归；
- 在干净 NVHPC + MPI 环境构建三/五对角库和示例；
- 冻结 28 槽五对角正确性与性能 baseline；
- 自动运行五项独立 Node 验证；
- 补齐输入检查、CUDA/MPI 错误检查和五对角 API 文档；
- 落地 28→22 通信裁剪，并证明与 28 槽数值等价；
- 在真实多 GPU 节点完成强扩展、弱扩展和通信消融；
- 完成一个制造解 Poisson/Helmholtz 集成 demo，或接入导师提供的现有 CFD/FFT 主程序；
- 形成代码、环境、配置、CSV、图表脚本可追溯的复现包；
- 完成一篇结构完整、结论不过度外推的论文全文；
- 补齐来源、许可证和引用说明。

### 争取完成

- plan 生命周期复用 host staging 缓冲；
- CUDA-aware MPI 与 host staging 对比；
- 将 22 槽裁剪推广为可生成的一般 `m` 槽位映射；
- 七对角 Fortran 原型或更高带宽性能探索。

### 明确不做

- 从零重搭完整 CFD 流场求解器、GUI 或可视化平台；
- 在同一任务中同时改数值算法、通信布局和 kernel 性能；
- 用单 GPU 多 rank 结果声称多 GPU 扩展；
- 以论文“录用”作为八周验收条件。

## 3. 当前基线与路线决策

审计评分为 `68/100`，选择“局部重构后优化”：算法和目录结构已有较强基础，独立数值验证可信，benchmark 也已成形；重写会丢失已有证据。主要阻断是 MPI 未初始化请求、许可不清、缺少干净构建和真实多 GPU 数据。

对应决策见 [[knowledge/wiki/decisions/ADR-001-优化现有五对角实现]]。

## 4. 8 周执行计划

### 第 1 周：可信基线与项目治理

软件：

- 确认正式 Git 仓库边界，加入 `.gitignore`，把历史产物与源码区分；
- 修复三/五对角模块中阻塞式 `MPI_ALLTOALLV` 后的无效 `MPI_WAITALL`；
- 补 `Nrow>=5`、`Nsys>0`、线程范围、rank 数和空分区检查；
- 在目标环境 `make veryclean && make all`，运行三/五对角单 rank和小规模多 rank；
- 把五个 Node 脚本接入一条 `check` 命令；
- 记录 baseline 快照、环境和原始输出；
- 核对上游 MIT 许可，补 LICENSE/NOTICE 和引用。

论文：

- 冻结研究问题、题目草案和主张—证据矩阵；
- 核验上游 PaScaL_TDMA 2.1 和最相关的分布式带状求解文献；
- 写“问题定义、研究缺口、贡献边界”初稿。

Gate G0：P0 修复、干净构建、独立验证、来源许可四项全部通过。否则不进入性能优化。

### 第 2 周：五对角正确性与 API 加固

- 建立小/中/边界尺寸测试矩阵；
- 对 28 槽 Fortran 结果做 CPU/稠密参考和多 rank 对照；
- 补 CUDA kernel launch、同步与 MPI 返回码检查；
- 明确系数/RHS 原位覆盖、plan 生命周期和 CUDA-aware 前提；
- 定位所有可能溢出的尺寸乘法和偏移，在设置阶段局部用 64 位检查；
- 记录 debug/release 构建和精度阈值。

论文：完成五对角缩约算法、数据布局、复杂度和验证方法草稿。

Gate G1：28 槽实现必须成为可由第二个人复现的正确基线。

### 第 3 周：28→22 通信裁剪

- 先在独立脚本中固定 22 槽映射和逆映射；
- 新增 28/22 同输入等价性测试；
- 只修改前向 pack/unpack 和描述符，不同时改通信模式；
- 保留 28 槽实现为可切换 baseline；
- 检查所有 rank、最小 `Nrow`、不均匀 `Nsys` 分区；
- 记录通信字节数、pack/unpack 时间和总时间。

论文：完成结构零槽定理、通信公式及五对角特例；谨慎区分“理论下界”“实现数据量”“实际网络字节”。

Gate G2：22 槽结果在冻结容差内等价，且通信量实测/日志与公式一致。

### 第 4 周：通信路径与内存优化

- profiler 确认 host staging 分配和同步的占比；
- 将 hA/hB 移至 plan 生命周期并复用，必要时尝试 pinned host memory；
- 在支持环境对比 host staging 与 CUDA-aware MPI；
- 每个优化作为独立消融，收益低于噪声则不保留复杂实现；
- 检查内存峰值、长时间重复调用和清理路径。

论文：形成 28、22、22+persistent、22+CUDA-aware 的实验设计和第一批图。

Gate G3：至少一项通信/内存优化带来可重复的阶段或端到端收益。

### 第 5 周：申报书衔接与一般带宽理论

- 审核 `m=1..6` 公式、递推和结构零槽证明；
- 将理论符号与五对角源码变量逐项映射；
- 补随机、边界、病态程度不同的独立数值测试；
- 完成制造解 Poisson/Helmholtz demo，报告网格误差和求解时间；若已有稳定 CFD/FFT 主程序，则改为接入其中一个线求解阶段；
- 有余力再选择其一：实现可生成的 22 槽描述符，或做七对角最小 Fortran 原型；
- 不要求生产级任意 `m` 求解器，避免扩张范围。

论文：完成一般化部分、CFD/PPE 应用关系和局限；所有“首次”表述暂留为待文献核验。

Gate G4：理论、脚本、五对角实现和论文符号一致，并且至少有一个 Poisson/Helmholtz 应用闭环。

### 第 6 周：真实多 GPU 实验与功能冻结

- 在每 rank 独占 GPU 的节点运行；
- 至少覆盖 1/2/4 GPU，条件允许再到 8 GPU；
- 做固定全局规模强扩展和固定每 GPU 工作量弱扩展；
- 对 28/22、staging/CUDA-aware 做消融；
- 重复不少于 5 次，报告中位数、波动、阶段时间、端到端时间和误差；
- 保存拓扑、作业脚本、环境、原始 CSV 和失败记录；
- 周末冻结 release candidate，停止增加功能。

Gate G5：论文核心图表都能由冻结脚本重建。若无法获得多 GPU 资源，缩小论文结论，不伪造扩展性主张。

### 第 7 周：独立复现与论文全文

Gate G6：产生可供导师逐段批注的完整论文 v1。

### 第 8 周：修改、归档与结题

- 按导师反馈完成最多两轮集中修改；

## 5. 论文设计

### 5.1 题目草案

中文：面向大规模 CFD 的通信裁剪多 GPU 五对角求解器：缩约结构、实现与性能评估  
英文：A Communication-Reduced Multi-GPU Pentadiagonal Solver for Large-Scale CFD Applications

题目需在文献检索与最终实验后再定稿。

### 5.2 预期贡献

1. 将 PaScaL 风格分布式缩约推广到五对角系统并给出可复现实现；
2. 给出一般半带宽 `m` 的接口规模、缩约带宽、槽位和通信公式；
3. 利用结构零槽把五对角前向数据从 28 裁剪到 22；
4. 在真实多 GPU 环境报告正确性、阶段性能、端到端性能与可扩展性。

贡献 2–4 必须由最终文献和实验决定措辞强度。

### 5.3 必备图表

- 分布式六阶段算法/数据流图；
- 一般 `m` 缩约系统结构示意；
- 28 与 22 槽位映射图；
- 正确性误差/残差表；
- 28/22 通信字节与阶段耗时消融；
- 1/2/4/8 GPU 强、弱扩展；
- staging、persistent、CUDA-aware 对比；
- profiler 或时间分解图。

## 6. 验收口径

### 正确性

- 独立 JS、CPU/稠密参考和 Fortran/MPI 结果形成三层证据；
- 不降低精度、不放宽残差来制造性能；
- 覆盖最小行长、不均匀分区、多个 rank 和重复 plan 调用；
- 无未处理 MPI/CUDA 错误、NaN/Inf、越界和未初始化请求。

### 性能

- 同硬件、精度、规模、rank/GPU 映射和计时范围；
- 报告绝对时间，不只报告加速比；
- 预热后重复至少 5 次，报告中位数和波动；
- 区分 pack、通信、缩约求解、update 与 total；
- 单卡数据只作开发基线，真实多 GPU 才支持扩展性结论。

## 9. 计划书、AGENTS.md、知识库和 Skill

- 本计划书：保存 8 周里程碑、Gate 和动态状态；
- 根 `AGENTS.md`：保存每次 GPT/Codex 工作都必须遵守的稳定规则；

- Skill：只保存可重复的“选一个任务—实现—验证—记录”流程。

现在已经可以使用 `AGENTS.md`，但不急于制作正式 Skill：至少先完成 P0 修复和一个 28→22 真实任务闭环，确认构建/验证命令稳定后再提炼 Skill。Skill 每次只执行一个就绪任务，不能一次跑完整个两个月计划。
