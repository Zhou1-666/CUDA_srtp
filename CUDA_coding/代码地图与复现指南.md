## 4. CUDA Fortran 构建

构建需要 Linux/WSL/HPC 上的 NVIDIA HPC SDK、MPI Fortran wrapper、GNU make 和 NVIDIA GPU。当前 Windows PowerShell 没有 `nvfortran/mpif90/make`；WSL2 + NVHPC 24.11 + OpenMPI 4.1.5 已用于 TASK-001/004/008 的干净构建和 `np=1/2` 回归，但仍是单 GPU 环境，不能替代真实多 GPU 验证。已有 `.o/.mod/.a/a.out` 仍不能代替重建。

在可用环境中，从源码根目录执行：

```bash
make veryclean
make all
mpirun -np 1 ./run/a.out
mpirun -np 1 ./run/a.out_penta
```

修复 P0 通信问题后，再用 `-np 2` 做足够小、每 rank 绑定独立 GPU 的回归。不要在一块 GPU 上过度订阅后把结果写成多 GPU 性能。

建议保留两套构建：

- debug：`-O0 -g -gpu=debug,lineinfo` 等适合 NVHPC 版本的检查选项；
- release：`-O3 -cuda` 加明确架构参数，并保存完整编译输出。

## 5. benchmark 复现

历史实验入口位于 `perf_bench/run_sweep.sh`，环境文件显示曾使用 WSL2、NVHPC 24.1、OpenMPI 4.1.7a1、RTX 4060 Laptop 8GB、host staging、10 次迭代。

论文级实验至少记录：

- Git 提交或不可变快照校验值；
- GPU 型号与数量、拓扑、驱动、CUDA、NVHPC、MPI；
- CUDA-aware MPI 是否启用；
- `Nsys`、`Nrow`、rank 数、rank→GPU 映射；
- 双精度、系数构造和误差真值；
- 预热次数、正式重复次数、中位数和波动；
- local、pack、forward MPI、reduced solve、backward MPI、unpack、update、total；
- 原始 CSV 与绘图脚本。

建议实验组：

1. 28 槽原始实现；
2. 22 槽结构裁剪；
3. 22 槽 + persistent host staging；
4. 22 槽 + CUDA-aware MPI；
5. 需要时再加入通信重叠，且单独作为一个消融变量。

TASK-013 已形成新颖性/外部 comparator 技术决策：P=1 必选 cuSPARSE，ScaLAPACK 条件式，一般 `m` 不作首次性主张；仍待非原推导者签字。TASK-014 的 28 槽 debug/release、np=1/2 正确性和五次单 GPU计时已经冻结；TASK-022 的隔离 cuSPARSE QR adapter、同配置五次计时和独立复审也已通过。两者只支持固定 P=1 solver-window 的受限比较。当前先执行 TASK-017 核验真实多 GPU环境；通信重叠只有在 TASK-020 的 profiler/关键路径 Gate 通过后才实施。

## 6. 正确性阈值

阈值需在第一周冻结，建议初始口径：

- 独立双精度脚本：误差/相对残差与当前机器精度量级相当；
- Fortran 小规模：与 CPU/稠密参考的 `Linf` 不高于已冻结 baseline 的合理倍数；
- 所有 rank 无 NaN/Inf、MPI 错误、CUDA launch 错误；
- 28 槽与 22 槽在相同输入上误差差异不超过预注册容差；
- 性能失败不能通过放宽误差阈值来“修复”。

具体数值应在可干净重建的 baseline 上登记到实验卡，而不是直接把历史 CSV 当永久阈值。
