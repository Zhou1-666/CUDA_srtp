# GPT 主力开发执行指南

> 适用项目：PaScaL CUDA Fortran + MPI 分布式带状求解器  
> 配套：[[SRTP项目完成计划书]]、[[项目结构与技术审计]]、[[代码地图与复现指南]]  
> 目的：让 GPT 承担主力编程，同时把数学、并行正确性和论文结论置于可验证边界内

## 1. 推荐结论

- 日常主力：`gpt-5.6-terra + medium`；
- 高风险 CUDA/MPI 诊断：`gpt-5.6-sol + high`；
- 一般带宽推导、22 槽证明、投稿前审计：`gpt-5.6-sol + xhigh`；
- 机械整理和固定格式：`gpt-5.6-luna + low/medium`；
- 不按“任务看起来大”直接上最高强度，而按错误代价、数学耦合和证据难度路由。

模型名称将来变化时，按“前沿 / 平衡 / 高吞吐”重新映射，并用本项目代表任务比较一次通过率、真实缺陷和返工成本。

## 2. 模型与推理强度矩阵

| 任务 | 模型 | 强度 | 原因/验收 |
| --- | --- | --- | --- |
| README、API、知识卡、普通构建脚本 | terra | medium | 以链接、命令和格式检查验收 |
| 小范围 Fortran 实现、输入检查、错误处理 | terra | medium/high | 编译与回归比长推理更重要 |
| `MPI_ALLTOALLV`、非阻塞请求、rank 分区诊断 | sol | high | 错误可能只在多 rank 暴露 |
| CUDA 竞态、越界、同步和设备/host 生命周期 | sol | high/xhigh | 需要跨 kernel、MPI 和内存路径推理 |
| 28→22 槽位映射实现 | sol | high | 必须逐方程映射并做等价验证 |
| 一般 `m` 的递推、结构零槽与通信公式 | sol | xhigh | 论文核心数学，需独立反证与边界检查 |
| profiler 数据解读、性能因果 | sol | high | 防止把同步、缓存或噪声写成算法收益 |
| benchmark/CSV/绘图脚本 | terra | medium | 冻结输入后机械可验收 |
| 大量日志分类、Markdown 格式、文件清单 | luna | low/medium | 不让它决定数学或论文结论 |
| 论文段落初稿 | terra/sol | medium/high | 只能从“已支持”主张写作 |
| 投稿前反方审稿 | sol | xhigh | 专找公平性、证据断链和过度声明 |

强度解释：

- `low`：机械任务，错误易被自动检查发现；
- `medium`：默认日常开发；
- `high`：跨文件、多约束、并行状态或复杂缺陷；
- `xhigh`：核心推导、架构决策、疑难正确性和最终审计。

## 4. 每次 GPT 任务闭环

1. 读取根 `AGENTS.md`；
2. 从计划当前周选择一个无阻塞的单一任务；
3. 读取一个相关 ADR/公式卡、目标代码和对应真值脚本；
4. 写任务合同，冻结允许修改范围和成功条件；
5. 先运行 baseline，保存失败/成功证据；
6. 做最小改动，不顺手重写邻近模块；
7. 按风险运行 Node 真值、NVHPC 构建、MPI 回归、sanitizer/profiler；
8. 报告绝对结果、未覆盖范围和已知风险；
9. 用新上下文或另一成员审查高风险变更；
10. 更新实验卡、ADR（如决策变化）和论文主张矩阵；
11. 给出用户可复制的复验命令、预期结果和未覆盖范围；
12. 从任务队列推荐唯一的下一任务，但不在同一任务中开始实施。

完整交接格式见 `knowledge/meta/task-handoff-protocol.md`。

## 7. TASK-001 历史复现模板

```text
修复三对角和五对角模块 pascal_a2av 中的 MPI request 生命周期错误。
首次审计发现阻塞式 MPI_ALLTOALLV 后等待未初始化 request；TASK-001 的代码修复和 WSL/NVHPC/MPI 目标验证均已完成。该提示词保留为复现和发布回归模板。
只修通信正确性和相关错误检查，不修改消元算法、28 槽布局、精度或 benchmark 输入。
先确认删除 WAITALL 与改为真实非阻塞通信的语义差异；本任务优先采取最小正确修复。
运行当前七项 Node 独立验证，并在 NVHPC + MPI 环境干净构建，执行 np=1/2 的三、五对角小规模回归。
返回代码差异、命令、结果、未覆盖 MPI 实现和一张实验卡。
```

推荐：`gpt-5.6-sol + high`。原因是缺陷涉及 collective 与 request 生命周期，但修复本身应保持最小，不需要 xhigh。

## 8. 28→22 任务提示词

```text
目标：把五对角前向缩约通信从每线 28 个 double 裁剪到 22 个。
先读取 verify/mband_theory.md，逐条列出四个边界方程保留/省略槽位，建立 22 槽 pack 与 32 槽 reduced-system 的可逆映射。
先新增独立 28/22 等价脚本，再改 Fortran 描述符、pack/unpack；保留 28 槽可切换 baseline。
禁止同时改用非阻塞通信、persistent buffer 或 kernel 融合。
验证随机系统、Nrow=5、非整除 Nsys 分区、np=1/2/4；报告误差、实际发送 count、各阶段绝对时间。
若理论映射、代码注释和数值统计不一致，停止并记录反例。
```

推荐：实现用 `sol/high`，最终公式和映射独立审查用 `sol/xhigh`。

领取前置：TASK-002A、013、014 和红队 G0-A/G1 必须通过；否则本提示词只可用于设计审查，不得改 Fortran。

## 9. 性能任务提示词

```text
先冻结硬件、精度、问题规模、rank→GPU 映射和正确性阈值。
本次只改变一个变量：<28/22、persistent staging、CUDA-aware 或其他>。
预热后重复至少 5 次，报告中位数、波动以及 local/pack/MPI/reduced/unpack/update/total。
同时运行正确性回归；局部变快但 total 无显著收益时，不宣称端到端加速。
单 GPU 多 rank 结果必须明确标注，不能写成多 GPU scaling。
```

## 10. 论文任务提示词

```text
只从 knowledge/wiki/paper/claim-evidence-matrix.md 中状态为“已支持”的主张写结果段。
逐项核对数字的实验卡、原始 CSV、图表脚本、环境和代码快照。
寻找不公平基线、精度或阈值变化、单卡结果外推、多带宽理论被误写成生产实现、28→18 错误以及“首次/最优”无文献支持。
问题按阻断投稿/重要/一般排序，不替证据不足的结论编造更漂亮表述。
```

## 11. 人工必须掌握的 Gate

GPT 可以在任务范围内读写代码、运行非破坏性测试、整理实验和生成论文初稿，但下列事项必须由人确认：

- 数学定理和核心递推的最终正确性；
- 上游许可、作者贡献、公开范围和投稿决定；
- HPC 资源与真实 rank→GPU 绑定；
- 论文的创新性、对比公平性和最终数字；
- 降低精度、改变基线或放宽正确性阈值；
- 删除历史原始数据或发布代码。

## 12. 独立审查设计

同一个 GPT 上下文不能同时充当需求、实现、测试真值和最终审稿人。建议：

- 实现者只看任务所需上下文；
- 审查者从稳定基线、公式和测试重新推理，不读取实现者的自我辩护；
- 数学变更要求一个脚本真值 + 一次独立推导；
- 性能变更要求 correctness reviewer 与 performance reviewer 分开；
- 论文数字由未编写对应 kernel 的成员抽查。

## 13. Skill 的创建时机

不要把八周计划全文做成 Skill。当前先使用根 `AGENTS.md` + 计划 + 知识库。满足以下条件后再创建 `pascal-sprint-executor`：

- P0 修复已在目标环境复现；
- 统一检查命令稳定；
- 至少完成一次 28→22 或 persistent staging 的“实现—验证—实验卡”闭环；
- 能明确任务类型到验证命令的映射；
- 用第二个真实任务验证该流程可复用。

未来 Skill 每次只选择一个就绪任务，执行、验证并记录；不得自动改变论文主线、验收阈值或对外发布状态。

核心原则：GPT 可以写大部分代码，但只有外部真值、目标环境运行和可追溯实验能决定代码是否完成、性能是否提升、论文结论是否成立。
