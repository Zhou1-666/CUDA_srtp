# ADR-003：红队评审后的 Gate 重构

## 决策

1. TASK-006 从 `ready` 改为 `blocked`，先完成 TASK-002A、013、014；
2. 把来源/贡献边界与最终许可文本拆为 TASK-002A/002B；
3. `G0-A` 管内部研究方向，`G0-B` 管公开发布/投稿，避免许可证文本无限阻塞内部验证，同时保留合规底线；
4. 第 1 周提前执行 TASK-017 多 GPU 环境 smoke，不等到第 6 周才发现资源/工具链问题；
5. 数值稳定性、动态内存、容量和扩展关键路径分别由 TASK-015/016/018/020 管理；
6. overlap 只有通过 TASK-020 的 profiler/关键路径 Gate 才能进入 TASK-021，不能与 22 槽或 persistent staging 混合；
7. 保留 28 槽可切换 baseline、三对角冻结参考和 claim-evidence Gate。

## 原因

- 当前代码正确性基础比初始审计更成熟，但论文归属、新颖性、公平外部对照和真实多 GPU 环境仍未闭环；
- README、计划和代码地图曾把已完成任务继续写成当前阻断，证明需要明确当前事实源与历史快照边界；
- 直接进入 22 槽实现会把低成本的论文致命风险推迟到实现之后；
- overlap、病态输入和显存容量是不同风险，合并处理会失去因果和验收边界。

## 后果

- 短期增加若干文献、来源和 baseline 任务，TASK-006 延后；
- 22 槽实现开始时将拥有冻结真值、贡献边界和公平实验协议；
- LICENSE/NOTICE 未完成时可以内部研究，但不能公开发布、投稿或对外再分发；
- 没有公平外部 comparator、没有 overlap 收益或一般 `m` 缺乏新颖性都允许成为负结论，不通过更换问题或过度措辞掩盖。

## 不改变

- 不扩张为完整 CFD 软件；
- 不删除三对角上游参考；
- 不修改已经通过的 TASK-001/004/005/008 证据；
- 不把一般 `m` 的 JS 验证写成生产级 Fortran 实现。

## 复核点

- TASK-002A/013/014 完成后复核 TASK-006 是否可转 `ready`；
- TASK-017 后复核第 6 周多 GPU 承诺；
- TASK-013/019 后复核论文题目和贡献 2–4；
- TASK-020 后复核是否创建 overlap 代码分支。
