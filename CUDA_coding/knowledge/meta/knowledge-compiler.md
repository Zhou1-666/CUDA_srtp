# 知识增量编译流程

## 触发条件

- `raw/inbox` 出现新资料；
- 来源哈希或网页快照变化；
- GPT 任务产生值得归档的 output；
- health check 发现缺口、矛盾或孤立页面；
- 新实验改变论文主张状态。

## 单次编译步骤

1. **登记**：分配 source ID，记录位置、哈希/日期、许可和隐私；
2. **抽取**：列事实、方法、数字、限制、引用位置和未知项；
3. **比对**：查 Wiki 是否已有相同概念、相反结论或待解决问题；
4. **计划**：决定更新既有页、创建新页、只登记不编译或拒绝进入；
5. **编译**：生成短摘要、概念页、反向链接和 source IDs；
6. **验证**：数字回查原文；数学/代码/性能按各自 Gate 检查；
7. **索引**：更新 `wiki/00-index`、brief、map 和相关页面；
8. **记录**：更新 compile queue/log 和健康报告；
9. **提问**：把未解决矛盾和新研究问题写入 `open-questions`。

## 编译提示词

```text
你是本项目的增量知识编译器，不是自由写作者。
读取一个 raw 来源、source registry、相关 wiki 页面和 schema。
先列出来源可直接支持/不能支持的结论，再决定更新或新建页面。
所有事实带 source ID；不确定项写未知，禁止静默补全。
保留矛盾双方，生成开放问题；不要覆盖 raw，也不要把 output 当原始证据。
最后更新索引、来源地图、编译队列和变更日志。
```

## 小批量原则

每次编译一个来源或一个紧密主题包。目录结构由现有索引和概念决定，不让单篇新资料随意重组整个 Wiki。累计 5–10 个来源后再运行一次跨来源综合与目录重构建议。
