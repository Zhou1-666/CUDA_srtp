# TASK-031 冻结后、论文前的多 GPU 优化顺序

> 用户于 2026-09-04 批准把多 GPU 源码优化提前到论文和 release 之前。本页只固化顺序、来源边界和验收合同；不启动 solver 修改、GPU 作业、发布、提交或合并。

## 1. 决策

原顺序“TASK-031 → TASK-011 论文 → 可选 TASK-032 release → 资源所有权优化”不再适合当前证据：TASK-009 的 P8 强扩展 speedup 只有 `0.389x–0.457x`，多 GPU 总时间甚至慢于 P1。先写论文会把明显的扩展性缺口固化进主结果，也会让后续优化重新生成图表和主张。

新顺序如下：

1. 完成 TASK-031，冻结当前正确性基线 A；不把 SRC-029 混入当前冻结任务。
2. 执行 TASK-033，只读审计 SRC-029 与 A 的精确差异，建立候选地图，不改 solver。
3. 新建一个单独的基线/瓶颈任务，冻结可由 P1 公平运行的强扩展 workload、计时口径和 P1/P2/P4/P8 现状；不得直接从 README 自报数字选方案。
4. 按瓶颈证据一次只实施一个候选。结构所有权、数值算法、通信后端和 kernel 调优不得混在一个任务或一个 A/B 中。
5. 每个候选先过正确性/SOP，再与同一 A 基线做正式配对性能实验；未达门则以负结果关闭并撤回，不叠加到下一候选。
6. 只有被独立接受的单项候选才可组成优化基线 B；B 重新通过组合正确性、1/2/4 GPU 强扩展、适用跨节点回归和完整指纹审计后，冻结为新的不可变版本。
7. TASK-032 从 B 导出内部精简 release；公开分发仍受 TASK-002B 和明确授权约束。
8. TASK-011 最后冻结论文 v1 的图表与主张；TASK-019 投稿前检索仍是投稿 Gate。

本设计只取代 2026-09-02 资源所有权设计中的排程和基线派生时点。该页对 plan-local 模式、persistent pageable/pinned 及禁用 chunked `MPI_IALLTOALLV` 的技术分析仍是候选参考，但不再具有直接实施资格。

## 2. 为什么 TASK-033 必须位于源码修改之前

SRC-029 solver 与 TASK-031 solver 有 1117 行文本差异。整包替换会同时改变未知数量的功能、安全合同、资源生命周期和性能路径，无法把收益归因，也可能回退 TASK-004/008/015 等已验证防护。因此冻结后的第一个优化动作应是 donor audit，而不是 merge：

- 固定 archive、solver 和 A 基线 SHA；
- 逐函数分类差异为“可迁移候选 / 旧实现差异 / 功能或安全回退 / 需证据”；
- 对每个候选写清所解决的测量瓶颈、允许文件、保持的不变量和最小 A/B；
- 只推荐一个下一任务，不提前把多个候选捆绑实现。

## 3. 多 GPU 性能硬门

“多 GPU 快于 1 GPU”是 B 版本及性能论文的必要条件，但 `1.001x` 或一次偶然胜出不能算通过。正式合同为：

- 使用普通 solver 的 rank-MAX `total_s_max`，不以 MPI 子阶段、单 rank、平均值或包内自报数字替代；
- 强扩展输入必须完整适配 P1，P1/P2/P4 使用相同全局问题、FP64、算法路径、slots、编译 flags、GPU 型号、节点类型、MPI/backend 和 rank→GPU 规则；
- 至少预注册两个代表性 workload；每组 2 次独立 warmup、10 次 AB/BA 交替的正式配对；保存每次绝对时间、误差、环境和完整源码/runner 指纹；
- 对每个 workload 和每个 `P ∈ {2,4}`，要求 `median(T1/Tp) >= 1.05`，且至少 8/10 对满足 `Tp < T1`；P2 或 P4 任一未达标，就不能冻结为“同节点多 GPU 加速版”，TASK-032/011 的性能链继续 blocked；
- 同时报告并行效率 `E_P=T1/(P*Tp)`。超过 P1 只是最低门，不得据此宣称接近线性扩展；
- 弱扩展另按吞吐/效率报告，不能用随 GPU 数变化的总问题规模与 P1 原始延迟直接比较来通过强扩展门；
- 数值误差、API/失败合同、内存生命周期或源码身份任一失败，性能样本作废，不允许用更快掩盖不正确。

`1.05x + 8/10` 是对计时噪声的工程下限，不是论文统计显著性的替代；正式报告仍给中位数、IQR/MAD和原始样本。

## 4. P8 与跨节点边界

P8 仍应在 B 的验证矩阵中运行，但必须区分代码扩展性和网络可用性：

- 若目标是声明跨节点多 GPU 加速，则 P8 也必须在公平强扩展输入上满足 `median(T1/T8) >= 1.05` 和 8/10 配对胜出；否则不得发布该主张；
- 若集群仍被强制 TCP/`eth0`、无法使用预注册生产网络路径，则把 P8 记为环境/跨节点 Gate 未解除，保留原始证据；不得把它写成通过，也不得用它否决已经独立通过的“同节点 P2/P4 加速”限定结论；
- 同节点 P2/P4 未过时，不能归咎跨节点 TCP，也不能继续进入 release/论文性能冻结。

因此，当前最低可接受目标是 P2 和 P4 都稳定快于 P1；P8 决定能否进一步声称跨节点加速。

## 5. 不变量与停止条件

- 不修改冻结三对角源码；
- 保持 FP64、`1e-10` 数值门、`64*epsilon*row_scale` 主元合同、错误码 4、28/22 布局及现有输入/索引拒绝合同；
- 保持 RHS/部分系数原位覆盖及 communicator/plan 生命周期的明确所有权；
- 资源所有权重构不与数值算法修改混合；性能候选不静默改变 MPI backend、网络、slots、线程或 workload；
- 任一候选出现错误、死锁、timeout、生命周期异常、指纹漂移或正式中位性能未达门，立即停止该候选并保留负结果；
- 未经实测不宣称更快；未拿到 SRC-029 原始 job 日志前，不复用其 README 的性能结论。
