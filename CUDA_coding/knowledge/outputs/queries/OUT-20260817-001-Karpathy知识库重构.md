# 根据 Karpathy LLM Knowledge Bases 思路重构项目知识库

## 问题

如何让当前 SRTP Obsidian 知识库随着来源、实验和 GPT 问答持续增长，同时保持科研证据可追溯？

## 结论

采用 `raw → wiki → outputs → meta` 四层结构，并引入 source registry、增量编译队列、页面 schema、压缩 brief、来源地图、健康报告和开放问题。问答不直接污染 Wiki，先进入 outputs；只有有来源且形成长期增量时才回编译。

## 与原帖相比的项目化增强

- 增加原始来源与 AI 派生产物的隔离；
- 使用 source ID、SHA-256、隐私等级和页面状态；
- 禁止静默填补科研数据；
- 数学、性能、论文主张有独立 Gate；
- 旧入口保留兼容跳转。
