# BSCC-N32-H 上执行 TASK-018 的操作注意

## 目的与边界

本文把用户提供的“各超算资源联网命令、Slurm 常用命令、module 使用介绍”（发布时间 2026-07-21）转为 TASK-018 的操作约束。它不是 N32H 专属手册，也不授权修改已提交的 Node.js 容量模型、运行器或任务合同。

当前已确认的目标环境应记录为：ParaAI / 北京超级云计算中心 `BSCC-N32-H`，N32H A14P 分区，A100-40，`gpu` 队列。TASK-017 已完成双 A100 绑定与 `np=2` 制造解 smoke；TASK-018 仍只验证容量模型与一个安全的 `np=1` smoke，不产生扩展性或 22 槽性能结论。

## 必须遵守

1. 登录节点只用于同步、编译和提交；不得直接运行 benchmark。A100 smoke 必须在 Slurm 分配的计算资源内执行。
2. 先运行已提交的 Node.js 容量模型的本地/受管环境自检、FIT 和受控 REJECT；`REJECT` 是运行守则，不能以真实 OOM 配置测试。
3. 22 槽仍是投影，不能报告为 A100 实测显存节省；不得启动 TASK-006。
4. 每次目标环境运行保存代码 SHA、节点/GPU UUID、驱动、NVHPC、MPI、CUDA、队列、rank/GPU 映射、命令和原始输出。

## 网络与代理：N32H 的安全判定

用户材料列出了 BSCC-A、A2、A21、A6、A8、M8、M9、AL、T、T6 等分区的不同代理地址与登录节点限制，但**没有**给出 BSCC-N32-H / N32H A14P 的代理、联网节点或模块根目录。

因此：

- 不得把任何 BSCC-A 系列的 `http_proxy` / `https_proxy` 地址复制到 N32H；代理地址是分区专属配置，错误设置可能导致连接超时、连接到错误服务或污染提交环境。
- `git pull` 的 443 超时首先按环境依赖处理：查阅 N32H 专属通知或向平台支持询问“GPU 队列/登录节点的 GitHub HTTPS 代理与允许联网节点”。
- 未获得 N32H 书面/平台回执前，不把“无 Node”或“某代理不可用”写为长期平台事实；只保留本次终端的原始输出。
- 本机 Node.js 可运行纯 JavaScript 容量模型并保存其独立日志；这不能替代目标 A100 的制造解 smoke，二者的环境元数据必须分开。

## module 与 Node.js

用户材料说明 `module` 只影响当前 shell；可用软件应先用 `module avail <name>` 查询，再用 `module show <name>` 确认路径和依赖。若当前 shell 没有 `module`，必须使用登录界面或 N32H 通知给出的模块初始化脚本，不能假设其他分区的 `/public1`、`/publicfs01` 等路径存在。

对 TASK-018：

1. 先确认集群 checkout 已包含 `main@9cbab6e`。
2. 单独确认 `node` 是否存在；若不存在，查询 N32H 平台提供的 Node.js 模块或受管二进制路径。
3. Miniforge/Conda 的 Python 安装说明只适用于 Python 包环境；它不等同于已安装 Node.js，不能替代 `penta_capacity_model.js`。
4. 不得因为 Node.js 缺失而新建 Python 模型、修改运行器或修改 TASK-018 合同。

## Slurm：TASK-018 最小运行纪律

- 用 `sinfo` 查看当前账号可用队列与节点状态；以实际 `gpu` 队列和站点限制为准。
- 用 `salloc` 获取交互式 A100 资源，或用 `sbatch` 提交一次性 smoke；长时间或可复现实验优先 `sbatch`，以免 SSH 断开终止任务。
- 用 `squeue -u $USER` 查询运行/排队状态；用 `scontrol show job <JOBID>` 保存实际资源分配；结束时按资源约定释放或取消作业。
- 在分配中运行前，确认每个 rank 的 GPU UUID 与 `CUDA_VISIBLE_DEVICES`；本任务仅需 `np=1` 安全 smoke，不能将其描述为多 GPU 性能结果。

## TASK-018 的证据顺序

1. 本机或受管 Node 环境：`penta_capacity_model.js --self-test` 通过。
2. 同一模型：`256×256×1024,P=1,budget=30 GiB` 为 `FIT`。
3. 同一模型：`512×512×2048,P=1,budget=30 GiB` 为 `REJECT` 且退出码为 2；该步骤不调用 CUDA。
4. 已分配的 A100：仅运行 FIT 规模、一次 iteration、manufactured 的 `np=1` smoke；保存原始日志和环境信息。
5. 将单次运行证据归档到 `knowledge/outputs/validation/TASK-018-*/`，再按任务合同更新台账、测试矩阵和运行手册。
