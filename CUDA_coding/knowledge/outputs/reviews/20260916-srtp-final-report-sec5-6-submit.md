## 五、研究过程

### 5.1 研究经过、步骤

本项目立项时面向大规模不可压缩流动计算，希望在 GPU 上加速压力泊松等核心子问题。进入实施后，课题组对已有基础作了核对：仓库中较为完整的部分，并不是整套流场软件，而是一套 CUDA Fortran 与 MPI 结合的分布式带状线性求解器。它继承公开的 PaScaL_TDMA 三对角分区求解思想，并已开始向五对角推广。FFT 降维、几何多重网格和标准流场算例当时尚不具备。若按完整 CFD 软件从零补齐，难以在本轮训练周期内形成可核验的结果。因此，实际研究将阶段性目标明确为三件事：把五对角求解器做正确、做可复现；利用缩约系统中的结构零减少前向通信；在真实多 GPU 环境中检验正确性与性能，并用制造解 Poisson/Helmholtz 问题证明该求解器能够作为后续 CFD 离散的底层模块。

研究工作按四个阶段推进。

第一阶段是摸清已有实现，并补齐后续实验所依赖的工程基础。我们首先厘清上游三对角代码与本项目五对角扩展的来源边界，区分继承部分与新增部分。随后检查分布式通信路径，修正一处不安全的等待，补全对非法网格规模、空分区、线程配置和通信域不一致等情况的输入检查，并使工作区或通信计数超出当前整数范围时在分配和启动之前失败，而不是进入错误的 GPU 访问。与此同时，用不依赖求解器运行时的独立程序，对五对角缩约结构、前向打包格式和一般半带宽计数关系作了对照。这一阶段结束时，求解器可在 NVHPC 与 MPI 环境中干净构建，并形成了可重复的 28 槽正确性基线。

第二阶段完成前向通信裁剪。五对角按进程划分后，每个进程在两端保留 4 个接口未知量。若按“每条边界方程 7 个数、再去掉可本地重建的单位对角”打包，一条线的前向数据为 28 个双精度数；其中另有 6 个位置在结构上恒为零。我们先用独立程序确认 28 槽到 22 槽的固定映射可以无损恢复，再在 Fortran 中保留 28 槽对照路径，并增加可切换的 22 槽实现。两种路径使用同一组输入比较数值差异，并补充动态内存检查以及反复创建、求解、释放的生命周期测试。该阶段只调整打包与通信布局，不改动消元公式，也不与性能优化混做。

第三阶段把求解器放到真实多 GPU 环境中检验，并完成最小应用闭环。实验在每进程绑定一块 GPU 的节点上进行，覆盖 1、2、4 GPU 以及双节点 8 GPU，同时比较主机中转与 CUDA-aware MPI，并保留 28/22 两种前向布局。应用验证没有重写整套流场程序，而是构造制造解 Poisson/Helmholtz 算例：在结构化网格上沿一个方向形成批量五对角线系统，调用本求解器，检查残差和网格加密后的误差阶。这一阶段要回答的问题很具体：多卡时解是否仍然正确、时间如何变化，以及该模块能否接到后续压力泊松或高阶线离散中使用。

第四阶段根据计时结果做诊断，确定哪些优化值得保留。阶段拆分表明，通信和数据搬运占比较高，但计算与通信重叠的收益不够稳定，因此没有把它做成默认功能。锁页主机缓冲等改动也做过对照：局部拷贝有时更快，端到端时间却没有稳定改善，因而没有并入主路径。在上述工作完成后，我们对源码、实验记录和验证结果进行了整理，形成本结题报告。

### 5.2 研究方法、关键技术

本项目采用“先核对、再实现、后上机”的办法，把公式、独立对照、求解器实现和集群实验分开验收，避免只凭一次 GPU 运行下结论。

在算法上，采用分布式缩约求解。各进程先在本地对五对角线做消元，只保留两端接口方程；全部接口未知量组成规模随进程数增长、但远小于原系统的缩约系统；求得接口值后再回代。该框架来自三对角分区方法。推广到五对角时，需要重新确认接口未知量个数、缩约系统带宽，以及哪些量必须通信、哪些量可以在本地重建。

在通信上，按结构裁剪而不是按经验删数据。前向打包时不传输单位对角，也不传输结构上恒为零的槽位；接收端按固定映射将 22 个数恢复为完整方程。这样只减少前向载荷，不改变数学关系。实现中始终保留 28 槽路径作为对照，以便判断裁剪后的结果是否仍然等价。

在验证上，用独立真值约束 GPU 结果。缩约结构和槽位映射先由独立程序检查，再与 Fortran 求解器比较；应用算例采用制造解，同时观察残差、前向误差和网格收敛阶。此外，针对弱对角占优、行尺度跨度较大以及近奇异或零主元等情况设置了专门算例：能够继续求解的给出误差范围，不能安全继续的则明确失败，避免只看残差偏小就认为解一定可靠。

在性能评价上，只比较相同输入、相同精度下的重复计时。单卡上的多进程结果只用于程序调试；扩展性结论均来自每进程独占 GPU 的作业。计时区分局部计算、打包、MPI、缩约求解和回写，预热后重复多次，取中位数。外部对照方面，在单 GPU、固定规模的五对角问题上接入 cuSPARSE 的 QR 路径，作为量级参考，而不是作为“全面优于现有库”的依据。

程序采用 CUDA Fortran 编写，编译环境为 NVHPC，进程间通信使用 MPI，热循环在 GPU 上完成。独立数学检查可在普通计算机上先行运行。求解过程中，右端和部分系数会被原位覆盖，因此调用时需要明确数组在求解后不再保持进入时的内容。开发与验证分别在本地环境和配备 A100 的计算节点上进行。

## 六、结果分析

下面按本轮实际完成的研究内容说明结果。有的结果与立项时对“多 GPU 一定更快”的设想并不一致，正文按实验数据写，并把相应限制一并说明。

### 6.1 求解器正确性与适用边界

独立检查、稠密对照与 CUDA Fortran 求解器可以对齐。在已测试的对角占优问题和制造解问题上，28 槽与 22 槽路径的差异保持在双精度舍入量级：剖面测试中最大均方根误差约为 \(4.3\times10^{-16}\)，无穷范数误差约为 \(6.7\times10^{-16}\)。输入检查也起到了预期作用。行数过小、系统数不合法、进程数多于系统数、线程配置或通信域不一致时，求解会在进入计算前被拒绝；工作区或通信计数超出当前 32 位整数合同时，同样会在分配或启动前失败。

数值稳定性方面，不能把“残差很小”直接等同于“解一定对”。对预先设定的弱占优系统、跨多个数量级的行尺度，以及受控的近奇异问题，求解器给出了可重复的误差范围；遇到零主元或过小主元时，则以明确错误停止。当前实现没有主元交换，因此不能推广为可处理任意病态五对角系统。这一点对后续接入 CFD 有直接意义：如果离散本身在局部失去对角优势，不能指望线性求解器自动把问题救回来。

与单 GPU 稀疏直接法的对照也只在限定条件下成立。在笔记本 GPU、双精度、规模为 \(64\times64\times1024\) 的制造解问题上，本求解器中位时间约为 3.65 ms；同一配置下 cuSPARSE QR 两次独立复测约为 5.6–6.7 ms。这说明在这条批量带状问题上，专用求解器至少不是明显更慢。该结果不能外推到多 GPU，也不能写成已经全面超过现有库。A100 上另一次相近规模的并列计时中，两者差距约百分之三，同样只适合作为量级参考。

### 6.2 前向通信裁剪的效果

把 28 槽减为 22 槽，本质上是去掉 6 个结构零。对当前五对角前向布局，这相当于前向载荷减少约 21.4%。独立映射检查覆盖了大量随机系统和故障注入情形，Fortran 中的可切换路径也与 28 槽在设定容差内保持等价。因此，就“这种布局能否无损编码”而言，结论是成立的。

时间上的收益则随配置变化。前向槽数减少，并不自动等于 MPI 总通信量或端到端时间按同一比例下降，因为回传、局部消元和打包开销仍然存在。在单节点双 GPU、主机中转、固定规模的一组对照中，22 槽相对于 28 槽的端到端中位时间约缩短 14.5%，差异主要出现在前向的设备—主机—MPI 一段，局部计算几乎不变。单进程时两者几乎没有差别；在个别设备直接通信路径上，22 槽还略慢一些。

由此可以得到一条比较清楚的认识：对这类带状求解器，真正还能继续压缩的，往往不是再换一种消元，而是把已经为零、已经可以本地重建的量从通信里拿掉。与此同时，必须把“少传了几个数”和“墙钟时间变短”分开看待。前者是结构结果，后者只有在通信已经明显占时间时才会稳定出现。

### 6.3 多 GPU 正确性与扩展性

真实多 GPU 实验是本项目中最能约束后续判断的部分。1、2、4、8 GPU 的强、弱扩展，以及主机中转与设备直接通信、28 槽与 22 槽的配对均已完成。双节点 8 GPU 的正式结果中，误差仍保持在 \(10^{-13}\) 量级，说明分布式路径在这些规模上是正确的。

性能则是另一回事。从 1 GPU 强扩展到 8 GPU，加速比约为 0.39–0.46，效率约为 4.9%–5.7%；弱扩展效率约为 10%–13%。也就是说，增加进程和 GPU 以后，端到端时间并没有按局部计算被分摊的比例下降，部分强扩展点甚至慢于单卡。阶段计时与这一现象一致：MPI 及与之相关的等待可以占到一半左右。我们据此评估过计算与通信重叠，预测中位收益约 11%，但在预先设定的稳定性条件下不够稳定，因此没有把它作为正式功能保留。锁页中转使设备与主机之间的拷贝有所加快，端到端却出现过回退，相关改动也没有进入最终路径。

对这一结果可以作如下理解。当前实现将大量独立线系统成批交给 GPU，单卡时计算已经比较充分；分成多卡后，每卡分到的局部消元减少，接口缩约系统和集合通信却随进程数变重。五对角每个进程保留 4 个接口未知量，缩约系统规模为 \(4P\)，进程增多后，通信和缩约求解会较快成为主导。此外，实验环境并不总是最理想的 GPU 直连路径，部分作业还经过普通网络传输，因此这里的扩展性数字不能当成硬件上限。

这一部分能够成立的结论有两句。第一，分布式五对角求解器在真实多 GPU 上可以得到与单卡一致的解。第二，就目前实现和已测规模而言，它还没有表现出良好的强、弱扩展。后一句不是失败，而是本轮最有用的限制条件：后续工作应优先处理通信路径、缩约求解和负载划分，而不是继续增加功能。

### 6.4 与流动计算问题的衔接

申报书中的 FFT、多重网格和完整流场软件，本轮没有作为交付内容实现。本轮完成的是一个范围更小、但能够说明问题的闭环：在四阶五点格式和 Dirichlet 边界的制造解 Poisson/Helmholtz 问题上，沿一个方向形成批量五对角线，交由本求解器计算。在双 A100、双精度、32 组算例中，观测到的最低收敛阶约为 3.99，最大缩放残差约为 \(4.4\times10^{-14}\)。这说明，在这条线求解路径上，离散、边界处理与线性求解是自洽的。

该结果不能代替方腔流、槽道流等标准算例，也不能代替完整的时间推进。制造解只说明在真值已知时这一段计算是对的，并不验证湍流模型、入口条件或整场守恒。据此，本项目的阶段性成果应表述为：完成了可接入 CFD/PDE 软件的多 GPU 带状求解核心，并在 Poisson/Helmholtz 子问题上给出了可复现的验证；而不是已经完成工业级流场软件。

### 6.5 主要认识

综合以上工作，本轮研究可以归纳为三点。

第一，五对角分布式求解已经形成一条可核对的技术链条：有独立对照，有真实多 GPU 作业，也有最小应用算例。在已测问题上，求解是正确的，输入检查和主元失败处理也与设计一致。

第二，利用结构零将前向数据从 28 槽减到 22 槽，在数学上成立，并且在通信已经可见的配置中能够转化为一定的时间收益；但这种收益随进程数和通信路径变化，不能写成换一种布局就全面加速。

第三，多 GPU 扩展性目前受通信和缩约系统制约。程序能够在 8 GPU 上给出正确结果，但强、弱扩展效率偏低。这一结果说明，后续若要真正服务大规模流动计算，关键不在继续扩大功能范围，而在改善通信与负载划分。

本项目没有把 FFT、多重网格和标准流场算例作为本轮完成内容，也没有把一般半带宽公式扩展为生产级任意带宽求解器。相关结果已整理为本研究报告；学术论文将在指导教师指导下继续完善后择机投稿。源码按项目安排用于团队内部后续研发，不作为开源发布成果。这样写，是为了让结题表述与实际完成的工作一致。
