2. **先做 G1。** 在从明确 main HEAD 创建的 `codex/` 隔离治理归档分支建立显式路径清单；保留首批原文与可逆映射。只做 G1 可作为下一独立任务，G2/G3后续分别审核，避免一次事务吞下全部历史。
3. **保留字节再提交。** `.gitattributes` 现仅保护 TASK-007/020、KB-GOV-002 等路径；新纳入的治理原件与快照需要精确路径的 `-text` 或等价字节保护。先核属性与暂存 blob SHA，不能只核工作区SHA；禁止原文换行清洗。既有 `*.out` 会忽略原始证据，纳入前逐文件决定，不全局解除。
4. **核 G2/G3 的依赖边界。** 显式列每个补丁的旧内容、治理内容、引用页及原件是否在提交集合或已有基线中；已缺失的外部材料要登记为外部依赖，不伪称干净clone能全部复验。冲突只在隔离分支审查，不覆盖主树实时排程。
5. **分组暂存与验收。** 按复现单元检查 staged diff、暂存内容SHA、知识元数据和适用链接；本地提交后用独立clone核归档字节/引用边界。旧 KB-GOV 验证器对历史工作区的保护检查不等于便携归档验收，不能通过删掉断言获得PASS。
