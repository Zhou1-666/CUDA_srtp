## 4. 通用实验合同

### 先冻结，再测量

- [ ] 冻结基准 SHA、工作树差异和目标文件 SHA；从明确版本打包。不能仅凭目录名或 detached HEAD 保证远端代码一致。
- [ ] 记录 GPU UUID/拓扑、驱动、CUDA、NVHPC、MPI 版本及实际通信后端、FP64、问题规模、rank/GPU 映射、CPU 绑定、slots、预热和重复次数。
- [ ] 首先使用合法小规模 `16×8×128`、P=1/2、28/22 smoke；本地行数必须 `Nrow>=5`，不使用历史失败的 `n3=8,np=4`。
- [ ] 性能主输入从安全的 `256×256×1024` 起步；先 1/2 GPU，再按容量与收益证据扩展到 4/8 GPU。单节点 2 GPU与双节点 2 GPU必须分别记录，不混组。
- [ ] 每次只改变一个因素。配置筛选阶段可减少组合，但胜出项须重新独立确认，不能用筛选中的最快样本作最终结论。
- [ ] 正式 A/B 每侧 2 次独立预热、至少 5 次独立启动，每次 10 个计时迭代；配对固定分配节点/GPU，交替 A/B 顺序。跨会话差异保留，不挑选有利会话。
- [ ] 在实验前冻结保留门槛。新候选建议门槛为总时间中位数降低至少 5%、至少 4/5 配对方向一致，同时报告 IQR/MAD 并确认收益不被波动淹没；这是规划建议，开始实验前确认并记录，不能回改 007/020 的历史门槛，不能将其称为统计显著性证明。

### 数值与计时边界

- 保持既有 API 拒绝用例、32 位索引预检、无主元交换适用域；不删除主元安全检查换速度。
- 代数 benchmark 的 RMS/Linf/cross 门槛保持 `1e-10`；TASK-010 的 PDE 离散误差用网格收敛判据，不能错误要求其解误差也小于 `1e-10`。
- TASK-010 要求 scaled residual `<=1e-10`，`64→128` 和 `128→256` 的 L2/Linf 观测阶均 `>=3.8`，32 组覆盖完整。
- 新计时字段追加而非覆盖旧字段；旧 CSV 仍可解析，缺字段不能静默记为零。诊断同步开销须与普通 solver 的外部总计时对照。
- 正式性能使用不带 nsys/ncu、且最终同步已包含在窗口内的端到端 rank-MAX；GPU 异步启动返回时间不是求解完成时间。历史 profiled 数据保留原口径，不与低扰动新基线直接相除宣称加速。
- 不将各阶段独立 rank-MAX 相加作严格关键路径；跨 rank 时间线若未校准时钟，只比较持续时间与本地顺序，不用绝对时间戳猜等待原因。
- 新实验保存构建、运行、退出码、原始 CSV、分析命令、SHA256SUMS 和采用/否定理由，进入 `knowledge/outputs/validation/`；失败和否定结果不删除。

## 5. 新任务合同

以下源码路径均相对 `CUDA_coding/CUDA_code/源代码/`。输出以 `knowledge/outputs/validation/TASK-<编号>-<日期>-<配置>/` 独立归档；未来新增工具的接口需在单任务设计中确定，本轮不伪造已存在的脚本或运行命令。

### TASK-023 — 通信、搬运与每 rank 关键路径直接诊断

- 单一目标：补齐 forward/backward 的 allocate、D2H、MPI-only、H2D、free 直接计时，区分传输候选与进程等待，形成各优化分支的测量依据。
- 文件边界：`src/PaScaL_TDMA_cuda_penta.f90` 的 timing/profile-only 路径、`perf_bench/benchmark_penta.f90` 的 CSV/低扰动测量入口、独立解析测试与诊断 runner；不改数值递推、普通 solver 语义或生产 MPI 后端。
- 验证循环：先写缺字段、损坏 CSV、错误方向归类、每 rank 记录丢失等解析失败用例；再增加字段并验证旧解析兼容；目标环境 clean build、28/22 host smoke、方向计时、普通入口总计时对照；device 只在 CUDA-aware smoke 后纳入。
- 验收：保存每方向直接计时、消息元素数/字节口径、各 rank 持续时间和诊断扰动；无法分离的等待原因明确记为未知。计数是应用 payload，不冒充网卡实际字节计数器。
- 停止：nsys 导出失败可回退计时；无 ncu 计数器权限不阻塞本任务；不得用旧比例拆分冒充新直接测量。足以判断“不优化”的证据也可关闭。

### TASK-024 — 通信路径与绑定配对实验

- 单一目标：验证当前用户权限下可用后端/绑定是否比冻结 TCP 基线更合适。
- 文件边界：诊断/提交脚本与分析回执；不改 solver，不修改系统 Slurm/MPI 配置，不装系统库、不联系管理员、不越过资源分配直接启动节点进程。
- 顺序：先环境能力与 MPI-only smoke；再按相同消息规模验证通信；最后相同求解输入 A/B。改变后端时保持绑定不变，测试绑定时保持后端不变。
- 验收：实际 backend、节点、CPU/GPU 映射、正确性、重复总时间和波动；CUDA-aware 可用与实际 RDMA 使用分开证明。
- 停止：后端不可用/权限不足则归档“不采用”；仅选定配置可用不代表所有网络问题已解决。024 不可用不阻塞 025。

### TASK-025 — pageable/pinned 主机搬运实验

- 单一目标：判断锁页内存能否降低 host staging 的完整成本，不是重做 TASK-007 的纯分配省时。
- 文件边界：五对角 `pascal_a2av` 及 profiled counterpart 的候选路径、相关 runner/测试；若需改变 plan 生命周期，先暂停此实现并按新证据单独审批，不静默复活 007。
- 顺序：先相同消息大小 pageable/pinned copy 微实验；核实锁页分配是否成功或回落普通内存；再在固定 backend 下做求解器 A/B。
- 验收：分配/注册、D2H、MPI、H2D、释放全部计入；正确性与失败释放用例通过，总时间满足冻结门槛才采用。不能用复制阶段变快掩盖总时间变慢。
- 停止：锁页限制、回落未识别、分配代价抵消收益、数值或生命周期回归。保持可用 host fallback，不称为零拷贝。

### TASK-026 — 固定 LHS、多 RHS 的适用性与收益审计

- 单一目标：确认真实目标调用中是否有跨多次求解不变的五条系数，而非仅利用 benchmark 人造重复。
- 文件边界：独立数学检查、调用序列/profile 和设计回执；不改生产 solver 或 TASK-010 冻结 PDE 合同。
- 必须回答：哪些系数/边界/分区不变、连续使用次数 K、哪些消元因子与缩约结果只依赖 LHS、额外内存，以及哪些变化使缓存失效。
- 验证：用独立稠密真值对同一 LHS 的不同 RHS 检查等价，改变任一系数/边界/分区时不得继续使用旧缓存。分别估计预处理成本、每 RHS 成本与内存，报告 `Tprep+K*Tsolve` 和原路径 `K*Tbaseline` 的适用 K 区间。
- 验收：有真实使用场景、可复核依赖推导、容量与收益估计才给出“值得实现”；只有相邻三对角论文或重复 benchmark 不足以解锁 027。
- 停止：系数每次改变或没有实际需求，以“不适用”关闭，027 保持不实施。

### TASK-027 — 条件式固定系数预处理复用实现

- 前置：026 肯定结论及独立合同审查，用户明确批准接口/生命周期设计；不是通用 22 槽进一步无条件压缩。
- 文件边界：五对角 plan/create/clean、候选预处理/重复求解接口、独立正确性与生命周期测试；保留原通用入口，不改三对角或擅自改变 PDE。
- 验证循环：先多 RHS 真值与缓存失效失败测试，再实现最小接口；覆盖原位输入所有权、错误回滚、100 次生命周期、28/22、P=1/2 后再真实多 GPU；复用系数但不能复用旧 RHS/旧解。
- 验收：同时报告首轮、预处理、稳态、含预处理的 K 次总成本与额外显存；不得只报稳态掩盖预处理开销。减少重复系数通信须另有布局等价证据。

### TASK-028 — pack/unpack 多 rank 启动合并

- 单一目标：在保持映射和消息内容不变时减少四组按 rank 循环的 kernel launch。
- 文件边界：普通/profiled solver 的 pack/unpack 调用与对应 kernel、28/22 独立布局测试；不混入通信后端、固定系数或数值算法变更。
- 验证循环：先覆盖不均匀 `Nsys/P`、P=1/2/4/8、28/22、最小合法尺寸与索引边界；再单独合并一组启动，验证等价；最后 memcheck/initcheck 和无 profiler A/B。
- Gate：023 若显示打包/启动占比很小，先以收益上界判断“不做”。当前 P8 每个进程约 32 次相关启动是候选证据，不等于已经浪费大量时间。

### TASK-029 — 消元内核 profile 与单变量调优

- 单一目标：先证实一个热点，再优化寄存器/访存或线程块中的一个因素。
- 文件边界：对应五对角 kernel 或 launch 参数及其测试/benchmark；不同时重写布局、融合 RHS、修改精度或删除主元检查。
- 顺序：编译器寄存器报告或 ncu 单内核数据；固定输入做线程配置筛选；胜出设置另取独立数据确认。参数调整不能破坏覆盖率和非法线程数拒绝合同。
- 验收：寄存器、spill/访存证据或明确工具不可得记录，加阶段和普通入口总时间；无证据不宣称存在 spill。若代码级改变需要不同数值递推，暂停另立算法合同。

### TASK-030 — 主元失败状态回传优化

- 单一目标：只优化失败标志回传/汇总，不弱化数学安全检查。
- 文件边界：五对角 pivot status helper、状态存储与 kernel 标记、相关故障注入/生命周期测试；禁止改变 `64*epsilon*row_scale`、错误码 4 和 fail-before-unsafe-use 时序。
- 验证：先多个系统同时失败、不同 rank 失败、正常系统、最小尺寸的测试；新汇总仍须报告约定的首个失败系统/阶段，零主元不能流入后续通信或回代；覆盖 race、同步和释放。
- Gate：先独立测当前标志复制/CPU 扫描成本；很小时不实施。不能用整个 local_compute 作为错误检查成本。

## 6. 模型与推理强度用法

- `terra/medium`：复制一条已审查命令、解释队列状态、上传/哈希/日志回收、整理既定表格。
- `terra/high`：环境脚本、实验调度和统计复算；因果分析或发现 MPI 兼容歧义时转 `sol/high`。
- `sol/high`：诊断归因、CUDA/MPI 实现、数值回归与默认代码审阅。
- `sol/xhigh`：固定系数数学依赖、缓存失效/生命周期、错误检测并发语义及难以消除的分布式正确性歧义；不用于等待排队或机械传输。
- 不默认使用 max/ultra，不因一次错误盲目升级；升级应针对明确推理缺口。模型不能替代干净构建、独立真值或实际 GPU 结果。

模型全名为 `gpt-5.6-terra` / `gpt-5.6-sol`，本会话工具元数据中可用。官方文档把 terra 定位于成本/能力平衡、sol 用于更高能力需求，并建议按任务验证推理强度；上面的任务分配是本项目建议，不是官方性能承诺。来源：[OpenAI Model guidance](https://developers.openai.com/api/docs/guides/latest-model)，核对日期 2026-08-26。
