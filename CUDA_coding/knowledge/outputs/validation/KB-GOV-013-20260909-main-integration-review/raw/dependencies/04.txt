# TASK-032：软件成熟后的精简 release 包

> **2026-09-04顺序修正：** 用户批准先完成TASK-031冻结A，再审计SRC-029、实施并验收单变量多GPU优化、冻结B，然后执行本release，最后冻结论文v1。本文原有“TASK-031后即可打包/无需等待性能候选”的语句由[新顺序设计](20260904-pre-paper-multigpu-optimization-sequence-design.md)取代；其他白名单、原件保留和发布权限边界不变。

## 用户需求与当前状态

2026-08-26 用户要求增加后期计划：“增加一个 release 版本，不带冗长的实验数据……只保留软件本身”。本页登记这一需求；不是当前打包、删除研究资料、移动集群文件或公开发布的授权。SRC-003P/024 为软件与已有验证背景，不是 release 已完成的证据。

任务状态：**blocked（待 TASK-031、SRC-029审计、单变量优化链及B组合验收）**。本次仅更新计划顺序。默认先制作内部使用的源码 release；包名、首个版本号、支持平台和交付对象在执行时确认，不预先声称已有 v1.0。

## 单一目标

从明确、已验收的冻结版本导出一个可独立构建和使用的精简软件包。研究仓库保留完整历史、论文、原始实验、失败记录与审计证据；release 包按文件白名单导出，不靠删除研究仓库来“瘦身”。

## 包内与包外

| release 包保留 | 研究仓库保留、不随包分发 |
| --- | --- |
| 五对角求解器及实际必需的源码依赖 | 原始实验 CSV、大体量日志、profiler 输出和性能图表 |
| 构建/安装文件与依赖、支持环境说明 | 历史作业目录、备份、传输压缩包和失败尝试 |
| 精简 README、API/所有权/适用域说明、更新记录 | 论文 PDF、知识库全文、任务台账、聊天与过程材料 |
| 最小调用示例、制造解示例和轻量 smoke 自检 | 完整研究验证运行结果；这些证据另行归档 |
| 必要版权、署名、NOTICE 及已确认适用的许可文本 | 账号信息、私钥、凭据、机器专属绝对路径及无关配置 |
| 版本号、源提交、文件 SHA-256、支持环境和验证摘要 | `.git`、临时文件、缓存，以及非该 release 干净构建的产物 |

“只保留软件”仍包括必要说明、许可与最小测试，不是只留一个无法复现的可执行文件。不修改数值门槛、不删除软件错误检查，不把缺少实验附件解释为缺少内部验收。

三对角源码和原论文始终保留在研究仓库。若当前构建仍依赖三对角模块，源码包保留必需依赖；若要解除依赖，另行批准构建兼容任务，不在打包时直接删除。二进制包可在以后按明确 NVHPC/MPI/CUDA/GPU 组合单独验收，本计划不承诺通用二进制。

## 以后执行的步骤与验收

1. **冻结输入。** TASK-031 的A基线保持不可变；TASK-033及后续单变量候选完成后，优化B通过组合SOP与P2/P4性能硬门。记录B的实际受测提交与文件哈希、支持环境、已知限制和内部验证证据位置。不能只用 HEAD 代表带未提交修改的实际源码组合。
2. **白名单导出。** 在新目录构造 `pascal-penta-<version>/`，保留原仓库和证据不动；记录包内文件清单及 SHA-256。此目录名是计划示意，不是现有文件。
3. **从包验收。** 仅用解压后的包，在干净目标环境构建并运行最小示例/smoke；不能暗中引用开发仓库、历史对象文件或个人路径。完整回归由研究验证环境执行并绑定同一源码哈希，不把庞大日志装进包。打包造成的源码/构建差异必须重新审查和验证。
4. **记录版本。** 保存版本/源提交/哈希、支持环境、更新记录、已知问题、精简验证摘要及内部证据索引；确认包内无实验大文件、凭据和无关路径。tag、release 上传及对外交付均需届时明确授权，不自动执行。

验收成功才把 TASK-032 标为 done；计划登记或压缩成功均不等于 release 可用。若缺文件、构建/smoke 失败、源码无法锚定或交付范围未确认，保留失败证据并停止交付，不降低测试门。
